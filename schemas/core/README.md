# Core schemas

领域无关记录的版本化 JSON Schema。

已实现：`research-task/v1`、`research-claim/v1`、`research-evidence/v1`、`research-run/v1`、`research-failure-observation/v1`、`research-failure-analysis/v1`、`research-case-package/v1`、`export-decision/v1`、`export-receipt/v1`（Phase 1）、`evaluation-case/v1`、`suite/v1`、`evaluation-run/v1`、`comparison-report/v1`（Phase 3，ADR-0006）、`evaluation-attempt/v1`、`evaluation-result/v1`（Correctness Reset CR4，ADR-0011）、`suite-comparison/v1`（Correctness Reset CR5，ADR-0012）、`artifact-record/v1`、`evaluation-envelope-closure-receipt/v1`（Correctness Reset CR6，ADR-0013）、`research-case-package/v2`、`research-pattern/v1`、`heuristic/v1`、`reuse-event/v1`（Phase 4，ADR-0007），`candidate-manifest/v1`、`artifact-closure-receipt/v1`、`context-bundle/v1`（Phase 7 P7A，ADR-0010），`context-material-assessment/v1`、`context-bundle/v2`（Correctness Reset CR8，ADR-0015），`candidate-eligibility-attestation/v1`（Phase 7 P7B1，ADR-0016）、`skill-candidate-bundle/v1`（Phase 7 P7B2，ADR-0017）、`skill-static-validation-receipt/v1`（Phase 7 P7B3，ADR-0018）、`skill-semantic-review-attestation/v1`（Phase 7 P7B4，ADR-0019），以及 `collaboration-window-plan/v1`、`collaboration-ticket/v1`、`collaboration-worker-outcome/v1`（Phase 7 P7F0–P7F2，ADR-0027）——三十四个均可发布，且图校验在同一提交中完整认识每个 family（见 `docs/architecture/core-interface.md`）。全部 schema 文本由合同测试的 golden SHA-256 pin 逐字节冻结，演进规则见 `docs/governance/SCHEMA_COMPATIBILITY.md`。

`comparison-report/v1` 作为已冻结历史 family 保持可读取、可渲染和可验证，但其按单个 run 的 metric dimensions 构造统计样本的公开 `compare()` 入口已在 CR5 退役并 fail-closed。新建比较必须使用 `suite-comparison/v1`：观测单位固定为完整 `case × seed × frozen envelope` 配对网格，指标分别分析，且显式记录预注册方向/角色、ROPE 或 guardrail 非劣效界值、paired permutation、paired bootstrap、Holm 调整和效应量。该 family 不是 `PromotionDecision`。

CR6 不改 P7A 三个 v1 family，而以 `artifact-record/v1` 和 `evaluation-envelope-closure-receipt/v1` 补上完整 evaluation-envelope 闭包。receipt pin 既有 candidate manifest 和恰好八个 Artifact records，并覆盖 candidate member bytes、authoritative head、tools、budget、public data、evaluator、generator、统计计划与 rollback target。`core_store` 必须提供精确 bytes，`bundle_member` 必须解析到 candidate member；只有 evaluator configuration 可使用 `hidden_evaluator`，且禁止 locator/明文输入并要求 principal-separated byte attestation。该 attestation 不是密码学身份或真实 hidden evaluator 执行证据。

CR8 保持 `context-bundle/v1` 冻结，以 plaintext-free `context-material-assessment/v1` 和 `context-bundle/v2` 增加 classification/taint、redaction/export disposition、retention/encryption/tombstone descriptor 与 byte/token 双预算。`prepare_context` 要求 policy 与 candidate materials 精确一一对应；restricted plaintext 在 builder 与 wrapper 两条路径均 fail-closed。token 数只是 UTF-8 byte upper-bound preflight estimate，外部 protected artifact 也只是 hash descriptor；两者均不构成 runtime usage、storage、身份或语义验证证据。

P7B1 的 `candidate-eligibility-attestation/v1` pin exact candidate、P7A byte-closure receipt 与来源 Cases，并把七项 eligibility criterion 的 evidence bytes 固定为名称/hash/大小。`ineligible` 与 `needs_more_evidence` 都是可发布终态；`eligible_for_payload_drafting` 只打开后续草拟 Gate，不证明 lineage/principal 的真实独立性，也不满足 semantic、fresh-session、private evaluation 或 PromotionDecision。

P7B2 新增 `skill-candidate-bundle/v1`。单一 `draft_skill_candidate_bundle` interface 只接受 P7B1 `eligible_for_payload_drafting` attestation、严格 UTF-8 candidate payload bytes 与同一 attestation 的七项 evidence bytes；`SKILL.md` 必须含且仅含 `name`/`description` frontmatter，其他成员限于 `agents/`、`scripts/`、`references/`、`assets/` progressive-disclosure 布局。payload 与 evidence 进入同一 closure root，但 evidence 仍在可安装 payload 外。该记录只证明结构草拟与字节闭包，不证明运行时发现、语义质量、fresh-session/private evaluation、PromotionDecision、发布、安装、激活或真实 Skill 使用。

P7B3 新增 `skill-static-validation-receipt/v1`。单一 `validate_skill_candidate` interface 重新绑定 exact P7B2 payload bytes，并对最小 `agents/openai.yaml`、正负 trigger 字符串、registry exact collision、Router 声明样例与 descriptor-only payload diff 执行 fail-closed 静态验证。`static_pass` 与 `static_fail` 都可发布；静态通过不证明 semantic review、真实 Router/Agent 行为、fresh-session/private evaluation、发布、安装、激活或运行时加载。

P7B4 新增 `skill-semantic-review-attestation/v1`。单一 `attest_skill_semantic_review_protocol` interface 绑定 exact P7B2 Candidate、exact P7B3 receipt 与仓库外 review evidence bytes，并验证 reviewer/drafter/static-validator 声明标签分离、shared-context 声明、七个固定语义维度和确定性协议结论。`protocol_accept`、`protocol_reject` 与 `protocol_inconclusive` 都只是协议工程结果；该 family 把真实独立 semantic-review、fresh-session/private evaluation、PromotionDecision、发布、安装、激活与 runtime claim 固定为 false。

P7F0–P7F2 新增 collaboration window、ticket 与 worker outcome 三个 family。单一 `run_collaboration_window` interface 冻结 target、claim/evidence standard、权限、输入 pins、总预算与停止信号，同时显式允许 worker 在 ticket 内选择、组合、放弃或替换方法。三槽位至少两条 direct/enabling、最多一条 hedge；额外预算至多一次且必须有 hash-bound 新机会证据。scope drift 会停止后续 dispatch，future route 只能提案、不能改写当前 target。当前仅有 deterministic in-process Adapter，因此 seam 是 provisional，记录只构成 synthetic contract evidence，不证明真实多 Agent 协作、身份独立、独立审查或 lifecycle authority。

计划中但未实现：通用 CandidateBundle、PromotionDecision（Phase 4 显式不交付，ADR-0007 决策 1）。这些条目仍是空白契约，不表示 schema 已实现。ExperiencePacket 已定性为 Experience Exporter 的派生产物，不作为 Core schema（ADR-0003 决策 9）。
